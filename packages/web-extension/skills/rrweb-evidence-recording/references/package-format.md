# The recording package, file by file

The zip is written by `src/background/export/build.ts` (`packageBundle`) from
the types in `src/evidence/types.ts`. Schema version 1. When a field here and
the code disagree, the code is right and this file needs a fix in the same
change.

## Top level

| file | written as | what it is |
| --- | --- | --- |
| `manifest.json` | pretty JSON | `schema_version`, `recorder_version`, `skill`, `generated_at`, `session {id, name, recorded_at, capture_mode}`, `counts {actions, requests, findings, screenshots}`, `files [{path, bytes}]` for every file but itself — read this to know what a file costs before opening it |
| `README.md` | markdown | the reading ladder, generated by the recorder |
| `flow.md` | markdown | one block per action (below) |
| `findings.md` | markdown | candidates grouped by rule, deduplicated, capped at 20 per rule |
| `summary.json` | pretty JSON | `[{seq, t, type, route, target, network: [{method, url, status}]}]` — `url` is path + query only |
| `actions.json` | compact JSON | `ActionRecord[]` |
| `network/index.json` | compact JSON | `NetworkRequest[]` with `sameAs` dedup — the largest file |
| `network/curl.sh` | shell | one reproducible `curl` per non-noise request, full headers and body |
| `console.json` | pretty JSON | `ConsoleRecord[]` |
| `storage.json` | pretty JSON | `StorageDelta[]` — localStorage / sessionStorage changes |
| `ui-state/digests.json` | compact JSON | `[{actionSeq, route, digestHash, digest}]` or `{…, sameAs}` |
| `app-map.json` | pretty JSON | `AppMap {nodes, edges}` — routes, nav items, tabs, dialogs, tables seen |
| `screenshots/action-NNNN-after.jpg` | JPEG | the viewport after action NNNN settled; a repeat of an earlier state is not stored again and `flow.md` points at the earlier file |
| `redaction-report.json` | pretty JSON | `{reason: count}` — what was removed at capture time and why |

Not in the package: the raw rrweb event stream, cookies. `rrwebId` on an
action is a mirror id, not a pointer into a file.

## `flow.md` block

```
ACTION <seq>  ·  <HH:MM:SS UTC>  ·  <route>
<label: Clicked "…" / Typed "…" into "…" / Navigated to … / Submitted "…">

NETWORK
  <METHOD> <path?query> → <status|FAILED> (<ms>)      up to 8 primary/secondary
    (ambiguous: overlapped with a nearby action)
    (completed after this action settled)
  … and N more primary requests
  (+ N lower-relevance requests omitted)                the noise tier

UI
  - <diff line>                                          route change, rows appeared/changed, control changed, alert/toast

STORAGE
  <area>Storage: <key> = "<value>"                       redacted values show [redacted:<reason>]

CONSOLE
  [<level>] <text, first 200 chars>                      up to 4

SCREENSHOT  screenshots/action-NNNN-after.jpg

DRILL-DOWN  actions.json#<seq> · network/index.json actionSeq=<seq> · ui-state/digests.json actionSeq=<seq>
---
```

A trailing `BACKGROUND ACTIVITY` section lists requests attributed to no
action (polling), grouped by URL with counts.

## `ActionRecord`

| field | type | notes |
| --- | --- | --- |
| `seq` | int | final order by timestamp; the join key |
| `t` | ms epoch | when the action happened |
| `type` | `click dblclick input key select toggle submit scroll navigate reload back forward redirect tab-open tab-close` | |
| `page` | `{url, route, title, tabId, frameId, frameUrl?}` | `route` is the path + query at the time |
| `target` | `TargetInfo?` | absent for navigations |
| `value` | string? | what was typed / selected / pressed |
| `keystrokes` | int? | for `input`: how many keystrokes were coalesced |

`TargetInfo`: `rrwebId?`, `selector`, `selectorCandidates[]`, `locator`
(Playwright-style, e.g. `role=button[name="Approve"]`), `tag`, `role?`,
`accessibleName?`, `text?`, `attrs {}`, `box? {x,y,w,h}`, `coords? {x,y}`.
Prefer `accessibleName`, then `text`, then `locator`; `selector` is a
structural fallback and is what a `body > div:nth-of-type(3)` label means.

## `NetworkRequest`

| field | type | notes |
| --- | --- | --- |
| `requestId` | string | CDP request id; stable within the recording |
| `method`, `url` | string | full URL |
| `status`, `statusText` | int?, string? | absent when the request failed or never completed |
| `resourceType` | string? | CDP type: `Fetch`, `XHR`, `Script`, `Stylesheet`, `Image`, `Other`… |
| `requestHeaders`, `responseHeaders` | `{name: value}`? | `authorization`, `cookie`, `set-cookie`, `x-api-key`… are `[REDACTED:header]` |
| `requestBody`, `responseBody` | string \| null? | text bodies only; cut at 256 KiB with `bodyTruncated: true`; credential-shaped keys inside JSON are redacted |
| `startTime`, `endTime`, `duration` | ms | |
| `failed`, `errorText` | bool?, string? | network-level failure |
| `initiator` | `{type, stack?[]}`? | who started it |
| `actionSeq` | int? | the action window it was attributed to; absent = background |
| `ambiguous` | bool? | overlapped two windows |
| `completedAfterSettle` | bool? | finished after the UI settled |
| `tier` | `primary \| secondary \| noise` | |
| `sameAs` | requestId? | in `network/index.json` only: same method, URL, status and bodies as that earlier entry, which carries the payload |
| `payloadOmitted` | `asset \| noise`? | in `network/index.json` only: headers and bodies were dropped — `noise` because a settings rule excluded the request, `asset` because its `resourceType` is code or media, not API data. `network/curl.sh` keeps the full non-noise request |

## `UIDigest` (one per action, after settle)

`url`, `route`, `title`, `capturedAt`, `headings[]`, `landmarks[{role, name?}]`,
`collections[{key, selector, label?, count, columns?[], sampleRows?[][], rowKeyHint?}]`
(tables and lists with their row counts), `controls[{selector, role, name?,
value?, checked?, disabled?, expanded?, selected?, state}]`, `status[{role:
alert|status|dialog|toast, text}]`, `counters {label: number}`, `textAtoms[]`
(visible text), `hiddenAtoms[]` (present but not visible), `digestHash`.

`state` is one of `visible-usable`, `visible-disabled`, `dom-only-hidden`,
`ax-ignored` — the last two are what `findings.md`'s "hidden" and
"inaccessible" rules are built on.

## `UiDataFinding` (behind `findings.md`)

`kind` (`count_mismatch missing_in_ui hidden_in_ui value_mismatch stale_in_ui
not_focusable truncated unreachable_nav hidden_tab incomplete_table
missing_pagination missing_filter_control api_field_no_ui
inaccessible_control inconsistent_state`), `summary` (always phrased as a
candidate), `evidence {route?, actionSeq?, selector?, jsonPath?,
screenshotRef?, apiValue?, uiValue?}`, `howToVerify`.

`findings.md` groups by `(kind, jsonPath, summary)` and prints the first three
occurrences of each group.

## `ConsoleRecord`, `StorageDelta`, `AppMap`

- `ConsoleRecord {t, level, text, source: console|exception|unhandledrejection|browser-log, stack?[], actionSeq?}`.
  `debug` lines dominate real sessions; filter by `level` first.
- `StorageDelta {t, area: local|session, key, op: set|remove|clear, value?, actionSeq?}`;
  a redacted value is `{redacted: true, reason}`.
- `AppMap {nodes[{kind, id, label?, accessibleName?, selector, parentId?, route,
  firstSeenAction, states[], reachedBy?}], edges[{from, to, via: click|nav|route}]}`.
  Node ids embed the full route, so they are long; `firstSeenAction` is the
  actionSeq to look at.
