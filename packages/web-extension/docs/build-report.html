What the live run caught that tests alone couldn't

The first pass threw URL.createObjectURL is not a function when building the download — MV3 service workers don't have it, unlike a normal extension page. Vitest can't reproduce that; only running inside a real service worker surfaces it. Fixed by base64-encoding the zip into a data: URL instead, which needs nothing beyond APIs the service worker actually has. Rebuilt, reran the identical scenario: clean.

05What's left before you'd trust it on a real app

untestedMulti-action session

The live run was one click. A real filter-then-approve-then-navigate flow, with the row-count diff and cURL output, hasn't been watched end to end yet.

untestedZip contents

Chrome confirmed the download completed; the actual unzipped flow.md against real captured data hasn't been read by a human yet.

not builtFallback-path live check

Only the CDP path (debugger attached) was exercised live. The no-debugger fallback — DevTools already open, or a page CDP can't attach to — is unit-tested only.

not builtPause mid-CDP-capture

Pause/Resume don't currently stop CDP network/console capture — only the rrweb stream. A paused session still buffers CDP evidence. Flagged, not fixed.

06Try it yourself

  1. yarn doctor — confirms Node/yarn/browser are ready
  2. yarn ext:build — builds packages/web-extension/dist/chrome
  3. Chrome → chrome://extensions → enable Developer Mode → Load unpacked → point at dist/chrome
  4. Open your DEV app, navigate to the state you want, then click the extension icon → Start Recording
  5. Use the app normally, then Stop Recording — a recording-*.zip lands in your Downloads folder
